# คูปองส่วนลดตามยอด ต่อท้ายเซียมซี (pos-lan / fortune)

Status: DRAFT รออนุมัติ · 2026-11-18 · ขนาดงาน: เล็ก–กลาง (ฟีเจอร์เดียว แตะโมดูล `fortune/` + หน้าต่างกรอกยอดใหม่)

## Intent / Why
Boss อยากให้ลูกค้าที่ซื้อถึงยอดที่กำหนดได้ส่วนลดสำหรับครั้งหน้า พิมพ์เป็นคูปองต่อท้ายใบเซียมซีบนกระดาษแถบเดียวกัน
ใบเสร็จพิมพ์จบก่อนเซียมซีเสมอ จึงลดบิลปัจจุบันไม่ได้ → เป็นคูปองครั้งหน้า (Boss เลือกแล้ว)

## Goals
- G1 ตั้งขั้นยอด→ส่วนลด เองในหน้าตั้งค่า (ไม่ต้องอัปเดตแอปเมื่อเปลี่ยนโปรโมชัน)
- G2 คูปองมีรหัสสุ่ม + วันหมดอายุ พิมพ์ต่อท้ายเซียมซี ใบเดียวกัน
- G3 ระบบรู้ยอดบิลโดยแคชเชียร์กรอกเอง (แบบ A) ผ่านช่องกรอกยอดเล็กๆ
- G4 เก็บประวัติคูปองที่ออกในเครื่อง + ช่อง "ตรวจรหัสคูปอง / ทำเครื่องหมายใช้แล้ว" กันใช้ซ้ำ
- G5 เตรียมทางอ่านยอดจากใบเสร็จอัตโนมัติ (แบบ B) โดยเก็บตัวอย่างไฟล์ spool จากร้านจริงก่อน (Boss จะส่งตัวอย่างมาให้)

## Non-goals
- ไม่ลดบิลปัจจุบัน, ไม่ผูกลูกค้า/เบอร์/สมาชิก, ไม่มีเซิร์ฟเวอร์ตรวจคูปองออนไลน์ (ตรวจที่เครื่องที่ออกคูปองเท่านั้น)
- ยังไม่ทำการอ่านยอดอัตโนมัติ (รอตัวอย่าง) — ออกแบบช่องเสียบไว้เท่านั้น

## Anti-goals
- ใบเสร็จไม่ถูกตัด หรือถูกตัดช้า เพราะฟีเจอร์คูปอง (ต้องถอยไปเซียมซีธรรมดา/ตัดอย่างเดียวเสมอ)
- ยอดที่กรอกผิดออกคูปองส่วนลดผิดโดยแคชเชียร์ไม่รู้ตัว
- งานหน้าเคาน์เตอร์ช้าลงมากเมื่อลูกค้าเยอะ

## Constraints
- โค้ดที่แก้ทุกจุดครอบ try/catch; ฟีเจอร์ปิดเป็นค่าเริ่มต้น (`couponEnabled:false`); แอป build จริงยังไม่เคยรันที่ร้าน
- ห้ามรัน `electron .` จาก source; เรนเดอร์ใบด้วย Edge headless / ทดสอบแยกด้วย node
- ข้อความ UI ภาษาไทย; เขียนไฟล์ไทยด้วย Write tool; release ตาม `docs/fortune-slip-handoff.md` (draft → `gh release edit`), เวอร์ชันถัดไป 1.9.2
- ใบเซียมซีถูก pre-render เก็บใน memory แล้ว (ESC/POS ปิดท้ายด้วยคำสั่งตัด) → คูปองต้องเรนเดอร์แยกต่อใบ ไม่เข้า cache

## Approaches (Boss เลือก C)
- A ใส่ยอดเองอย่างเดียว · B อ่านยอดจาก spool (ยังไม่รู้ว่าทำได้) · **C = A + เก็บตัวอย่าง spool เพื่อประเมิน B (เลือก)**

## Design
### ยอดค้าง (pending amount)
- หน้าต่างเล็กลอยค้างบนจอ (always-on-top, เล็ก, ไม่แย่งโฟกัสนาน) ช่องเดียว: พิมพ์ยอด → Enter → แสดง "ยอดรอ: 850 · จะได้คูปอง 5%" + ปุ่ม "ล้าง"
- เมื่อใบเสร็จ Sea & Hill จบ (`handleDone` เดิมที่ผ่าน `wantsSlip`) ใช้ยอดค้างครั้งเดียวแล้วล้างค่า; ไม่มียอดค้าง = เซียมซีธรรมดา (ไม่ออกคูปอง)
- ยอดค้างหมดอายุเองใน 10 นาที (กันบิลก่อนหน้าไปตกกับลูกค้าคนถัดไป); แสดงเวลาที่เหลือ
- เปิดหน้าต่างจากปุ่มใน renderer (ถัดจาก 🥠) และเมนูถาด (ผมตัดสินใจเอง: ไม่ใช้ hotkey เพราะ Sea & Hill ใช้ F2)

### ขั้นส่วนลด + คูปอง
- ตั้งค่าใหม่: `couponEnabled`(false), `couponTiers: [{min:number, percent:number}]` (ตัวอย่างตั้งต้น `[{500,5},{1000,10}]` — ตัวเลขเป็นของ Boss แก้ได้), `couponValidDays` (30), `couponPrefix` ('SH')
- เลือกขั้นสูงสุดที่ `ยอด ≥ min`; ไม่ถึงขั้นแรก = ไม่ออกคูปอง
- รหัส = prefix + 6 ตัวอักษรสุ่มจากชุดไม่กำกวม (ไม่มี 0/O/1/I) ด้วย `crypto.randomInt`; ชนกับที่ออกไปแล้วให้สุ่มใหม่
- เนื้อหาคูปอง (เรนเดอร์ใน `slip.html` ฟังก์ชันใหม่ `renderCoupon`): "คูปองส่วนลด N% · ใช้ได้ครั้งเดียว · รหัส XXXXXXX · หมดอายุ วว/ดด/ปปปป (พ.ศ.) · เมื่อซื้อถึง… (ถ้ามีเงื่อนไขขั้นต่ำ)" (ตัวหนังสือแบบเดียวกับใบเซียมซี)
- ลำดับพิมพ์: `[เซียมซี ไม่มีคำสั่งตัด] + [คูปอง ปิดท้ายด้วย ESC d 2 + GS V 65 0]`; ถ้าเรนเดอร์คูปองพลาด → พิมพ์เซียมซีเดิม (มีคำสั่งตัดอยู่แล้ว) ไม่ออกคูปองและไม่บันทึกคูปอง

### ประวัติ + ตรวจคูปอง
- `userData/fortune-coupons.json` : `[{code, percent, amount, issuedAt, expiresAt, usedAt|null}]` (บันทึกเมื่อพิมพ์สำเร็จเท่านั้น)
- หน้าตั้งค่าเพิ่มส่วน "คูปอง": สวิตช์เปิด, ตารางขั้น, วันหมดอายุ, ช่อง "ตรวจรหัส" → ผลลัพธ์ ใช้ได้ N% / หมดอายุแล้ว / ใช้ไปแล้วเมื่อ… / ไม่พบ + ปุ่ม "ทำเครื่องหมายว่าใช้แล้ว"

### เก็บตัวอย่าง spool (G5)
- `tools/capture-spool.ps1` (รันด้วยสิทธิ์ผู้ดูแลระบบ เพราะโฟลเดอร์ spool อ่านไม่ได้ด้วยสิทธิ์ผู้ใช้ — ตรวจแล้วบนเครื่องนี้ได้ Permission denied): เฝ้า `C:\Windows\System32\spool\PRINTERS` คัดลอก `.SPL/.SHD` ที่ปรากฏไปโฟลเดอร์ปลายทาง ใช้ได้โดยไม่ต้องมีแอปใหม่ ตั้งให้ไดรเวอร์ "เก็บเอกสารที่พิมพ์แล้ว" (Keep printed documents) หากจำเป็น
- ผมจะวิเคราะห์ตัวอย่างที่ Boss ส่ง: ถ้าเป็นข้อความ/ESC-POS ที่ดึงยอดได้ → ทำแบบ B เป็นรอบถัดไป ถ้าเป็นภาพ/EMF → บอกเหตุผล
